Morris 的 QA 自動化學習筆記

紀錄從手動測試走向 Python 自動化架構的每一步

作業一：API 數據抓取與報表自動化

目標： 取代人工撈單，自動化整理後台遊戲數據。

  • 根據兩個 API 抓取資料，轉換後台對應數據並自動寫入 Google Sheet。
  • 將數據清晰分類為三大報表：「盈利報表」、「會員點數明細」、「異常局號」。
  • 異常局號定義邏輯： 精準判斷玩家在「追殺局」中，贏的金額是否超過其投注額的 5%。

作業二：Allure 測試報告整合與部署

目標： 讓測試結果視覺化，並實現團隊無障礙資訊共享。

  • 將作業一產出的 Google Sheet 測試內容整合進 Allure 測試框架中。
  • 自動執行腳本後，精準判斷異常資料並於報告中標示為 PASS 或 FAIL。
  • 建立內網 IP 伺服器或轉跳外網服務，提供固定連結，讓所有團隊成員可以直接點擊檢視最新報告。

作業三：QA 單號統計與部門績效分析

目標： 整合 Google Sheets 任務、Jira BUG 與 Worklog，依月份快速掌握 QA 團隊工作量。

  • 依年份與月份讀取已完成及當月進行中工作表，分開計算手動和自動化負責單數。
  • 統計成員 BUG 開單、QA Worklog 人日，以及每接一個任務平均開出的 BUG。
  • 以圖表呈現任務類型、成員工作量與每日趨勢，並匯出保留網頁色彩的 PDF。
  • 提供可修改的完整原始碼、Windows 啟動腳本與內網共用方式。

作業四：Git / GitHub 版控實戰

目標： 建立資深工程師的基礎素養，確保程式碼安全與可追溯性。

  • 練習將本地端程式碼上傳至 GitHub。
  • 落實「推版前再三確認」的良好開發習慣。
  • 熟悉 Revert (退版) 流程，確保當錯誤發生或遇到預期外狀況時，能第一時間安全還原程式碼。
